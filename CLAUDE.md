# RateThatJob.com

Product & technical spec: @SPEC.md
Project background (Hungarian): docs/osszefoglalo.md · Brand sheet: docs/brand-sheet.webp

## Stack
Next.js (App Router, `cacheComponents`) + TypeScript, Tailwind CSS v4, next-intl, Supabase, Vercel.

- Routing: all pages live under `app/[locale]/`. English at the root, Hungarian under `/hu` (`localePrefix: "as-needed"`, see `i18n/routing.ts`). `proxy.ts` handles locale negotiation.
- UI copy: never hard-code strings – add them to `messages/en.json` and `messages/hu.json`. Client components only receive the namespaces listed in their layout's `NextIntlClientProvider` (`pickMessages` in `lib/client-messages.ts`: root, `app/`, `business/`, `admin/` layouts) – add new client namespaces there. `npm run check:messages` (`scripts/check-client-messages.mjs`) follows imports from every page/layout and lists client namespaces a layout doesn't pass.
- Brand tokens: `app/globals.css` (`signal`, `ink`, `paper`, `slate`, `mist`, `tracking-brand`, `tracking-tagline`). Never use `signal` green as text on a light background.
- Brand files: `public/brand/` (logo on light/dark, icon, app icon).
- Supabase clients: `lib/supabase/server.ts` (calls `await connection()`: the auth client reads `Date.now()`, so anything using it renders at request time), `lib/supabase/client.ts`. Env vars: `.env.example`.
- Public data: `lib/data/index.ts` (`"use cache"`). Reads the `public_locations` / `public_reviews` views when Supabase env vars are set, otherwise `lib/data/sample.ts`.
- Database: `supabase/migrations/` (schema + RLS), applied automatically before every Vercel build by `scripts/migrate.mjs` (uses `POSTGRES_URL_NON_POOLING` from the Supabase ↔ Vercel integration; tracked in `supabase_migrations.schema_migrations`). Migrations must be new files, never edits of applied ones, `supabase/seed.sql` (local sample data). The public never reads `reviews`, `profiles` or `invites` directly – only through the `public_*` views. Score aggregates: `recompute_location_scores()` (service role).
- Public routes: `app/[locale]/[company]/[location]` (location page, JSON-LD, hreflang) and `.../reviews` (filters, pagination). These block instead of streaming (`instant = false`) so unknown slugs return a real 404.

- Reviewer flow (`app/[locale]/app/`, noindex): `sign-in` (email OTP, OAuth buttons from `AUTH_PROVIDERS` in `lib/site-config.ts`: empty for now = email code only everywhere, no buttons or "or" divider, title `Auth.titleEmail`; Google/Facebook/Apple can be added back; `?for=business` = employer sign-in, work email code only, set automatically by `requireUser()` for `/business` paths, skips the display-name step); its back arrow (`components/app/back-button.tsx`) goes `router.back()` when `HistoryTracker` (`components/history-tracker.tsx`, in the locale layout) saw an earlier page on this site, else to `next` (unless that is a protected `/app`/`/business` path) or home / `/employers` → `/auth/callback` → `welcome` (display name) → `rate` (workplace search) → `rate/[locationId]` (3-step form, `components/app/review-form.tsx`). Server actions: `app/[locale]/app/actions.ts`; validation: `lib/review-input.ts`. Review first, sign in after: `/app/rate`, `/app/rate/new`, `/app/rate/[locationId]` and `/app/rate/pending` (a map pick `?place=&name=&address=` or a typed workplace `?company=&address=&city=&country=`, `parsePendingWorkplace()` in `lib/workplaces.ts`) work signed out; the draft is kept in localStorage `rtj-review:<target>`; the last step (`components/app/review-sign-in.tsx`) asks for the email code (anonymity copy, optional job alerts consent `profiles.job_alerts`/`job_alerts_at`, off by default, toggle on `/app/account`), then `submitReview(input, invite, workplace, jobAlerts)` creates the workplace (`createManualWorkplace`/`createPlaceWorkplace`) and the review; new reviewers then go to `welcome?sent=1`. An email-link sign-in returns to the same page and sends the saved draft automatically. Place search before sign-in is rate-limited per IP. `proxy.ts` refreshes the Supabase session on `/app` paths only.
- Publishing: reviews are inserted as `pending_moderation`; a DB trigger (`private.moderate_review`) schedules them (anonymity delay) or holds them for the manual queue with `hold_reason` (contact details/links, fraud signals: `burst`, `new_account`, `many_locations`), and pg_cron runs `publish_due_reviews()` every 15 minutes. After submit, `processNewReview()` (`lib/translation-jobs.ts`) runs the Claude moderation check (`lib/moderate.ts`; flagged → `hold_review()`, reason `ai:…`) and then translation. Verification files go to the private `verifications` storage bucket under `<user id>/`.

- Workplaces: reviewers add missing ones via `create_workplace()` (`/app/rate/new`); company pages at `app/[locale]/[company]`. With `SUPABASE_SECRET_KEY`, `/app/rate` and `/app/rate/new` also search the map (Google Maps with `GOOGLE_PLACES_API_KEY`) (`lib/places.ts`, Places API New, session tokens; actions in `app/[locale]/app/rate/places/actions.ts`, UI `components/app/place-search.tsx`): one workplace per `google_place_id`, created server-side by `workplace_from_place()` (service role only; attaches the place id to a matching hand-entered location). Without a Google key the same UI searches OpenStreetMap (`lib/osm.ts`: Photon for search-as-you-type, one Nominatim `lookup` per pick, User-Agent, `"use cache"`, ≤ 1 Nominatim request/s, per-user limits, OSM attribution under the results): ids `osm:node/123`, stored as `locations.osm_id`, created by `workplace_from_osm()`, known ones via `locations_by_osm()`; `placesProvider()` picks Google first. Both are biased to an area (`lib/search-areas.ts`): the "Near" select next to the field (preset cities incl. Dubai/Abu Dhabi, "My location" via the browser only on request, rounded, "Anywhere"; remembered in localStorage `rtj:area`), else Vercel IP geolocation headers, else hu → Budapest; a picked city keeps results in its country; results show street, postcode, city, country. Countries for hand-entered workplaces: `COUNTRIES` in `lib/countries.ts` (incl. AE; `currencyFor` AE → AED, monthly pay in HU/AE).
- Categories: `lib/categories.ts` (29 keys = enum `workplace_category`, `CATEGORY_SLUGS` for `/city/[city]/[category]`, `MAIN_CATEGORIES` shown as chips, the rest under "More" in `components/category-chips.tsx`; names `Categories.<key>`/`<key>Plural`). Dropdown `components/category-select.tsx` (A–Z, empty = "Let us decide"): map types first (`categoryFromGoogle` with `primaryType`, `categoryFromOsm`), then Haiku (`lib/categorize.ts`), else `other`. Admin override on the Workplaces tab (`admin_set_location_category`). New categories: `alter type … add value` in a new migration.
- Account (`/app/account`): reviews and statuses, "I've left this job" (`mark_job_ended`), JSON export, sign out, delete account (`delete_my_account`).
- Admin (`app/[locale]/admin`, noindex): claims, moderation, documents, disputes, reports tabs, calling the `admin_*` RPCs; tools: legal entities (`admin_link_entity` → verified "Operated by"), workplaces (change company/location slugs → `slug_redirects`, resolved by `findRedirect()` in `lib/data/redirects.ts` with a 301) and CSV import (`admin_import_locations`, seeded workplaces). Admins are rows in `public.admins`. Decided verification files are deleted from storage.
- Follows & notifications: `toggle_follow()` (`components/follow-button.tsx` on the location page, list on `/app/account`); DB triggers write in-app `notifications` (review published, employer reply, application status, new review/job at a followed place, new application for managers), shown at `/app/notifications` and as the bell in `AccountLink`. Helpful votes: `vote_helpful()`, `helpful_count` in `public_reviews`. Admin "Metrics" tab: `admin_metrics()` (SPEC PMF signals).
- Reports: readers flag reviews on public pages (`components/report-button.tsx` → `reports`), one open report per person and review.
- Site chrome & static pages: `SiteHeader` (desktop nav, `MobileMenu` on phones, `LocaleSwitch` dropdown with flags), `SiteFooter` rendered from the locale layout through `FooterGate` (hidden on `/business`, `/admin` and the rate/apply forms). `/about`, marketing pages `/ratethatjob-index` (how the Index works, example badges from `lib/marketing-examples.ts`) and `/careers-hub` (RateThatJob Careers Hub = the jobs widget, `components/marketing/jobs-widget-example.tsx`, `/career-page` 301s there; both with FAQ, in the sitemap and reserved slugs), `/pricing` (plans; Pro per location in `lib/site-config.ts` `PRICING`: 39 EUR / 12 900 Ft a month, yearly = `YEARLY_MONTHS` × monthly; chains on request), legal pages `/terms`, `/privacy`, `/cookies`, `/imprint` from `content/legal/<page>.<locale>.md` (rendered by `lib/markdown.tsx`; `{{name}}` etc. filled from `OPERATOR` in `lib/site-config.ts`). FAQ blocks: `components/faq.tsx` (FAQPage JSON-LD).
- Home "near you": `components/home/near-you.tsx` streamed in `<Suspense>` (the rest of the home page stays static/cached), city from `visitorArea()` in `lib/visitor-area.ts`: cookie `rtj_area` (shared with the map search's "Near" select via `lib/area-client.ts`; "My location" only on request, rounded) → Vercel IP headers → `rtj_tz` time zone cookie → hu → Budapest; data `getNearby()` in `lib/data/nearby.ts` (city → country → all, never empty). `AreaPicker` next to the section title and in the desktop header. Cookies listed on /cookies.
- Discovery & SEO: `/search` (noindex, follow), city hubs `/city/[city]` and `/city/[city]/[category]` (`CATEGORY_SLUGS` in `lib/format.ts`), sitemap index `app/sitemap.xml/route.ts` → `app/sitemaps/*`, `app/robots.ts`, OG image per location (`opengraph-image.tsx`, Archivo fonts in `assets/fonts`).
- RateThatJob Index: `lib/rtj-index.ts` (SVG badges), `/embed/[id].svg?style=&locale=`, `/embed/[id]` (iframe card), `/embed/[id]/seal.svg`, `/api/public/locations/[id]/index` (JSON, CORS open), `public/widget.js`, generator at `/business/index` (also lists embedding websites from `embed_referrers`, recorded by `recordEmbed()`; badges are browser-cached only so every site is counted). Score shown from 5 reviews; seal at 4.0+ with 10+ verified. The Index on embeds is Pro: `public_locations.index_active` (`private.pro_active()`: trial or paid) → otherwise badges/card/seal render "currently unavailable" (`renderUnavailable`) and link to the profile, JSON `status: "inactive"`. RateThatJob Careers Hub ("Careers Hub", the jobs widget, free): `<div data-rtj-jobs="job|location|company" data-id data-theme data-locale>` in `public/widget.js` (Shadow DOM, featured jobs first, RateThatJob Index footer always shown) reads `/api/public/jobs?job=|location=|company=&locale=` (`lib/jobs-widget.ts`, open jobs from `public_jobs` only, CORS open, browser-cached, per-IP limit in `lib/rate-limit.ts`, `recordEmbed()` per location); Apply goes to `/app/apply/[id]?ref=embed&from=<host page>` in a new tab → `job_applications.source = 'embed'` and a "Back to the company's website" button. Generator: "Careers Hub" tab on `/business/index` (`components/business/jobs-embed-generator.tsx`).
- AI models: all model ids and `max_tokens` in `lib/ai-models.ts` (`AI_MODELS`: Haiku for translation and moderation, Sonnet for the candidate summary and follow-up questions; shared `aiClient()`). API failures (no credit, outage) never throw: translation is skipped (daily cron retries), moderation holds the review with `ai:unavailable`, candidate help is skipped.
- Machine translation: `lib/translate.ts` (Claude, `ANTHROPIC_API_KEY`) detects the language and translates review/reply text into every locale; `lib/translation-jobs.ts` stores it with the service-role client (`lib/supabase/admin.ts`, `SUPABASE_SECRET_KEY`). Runs via `after()` on submit/reply and daily from `/api/cron/translate` (`vercel.json`, `CRON_SECRET`). Skipped silently when keys are missing. Display: `components/translated-text.tsx` (`TranslatedText`) shows an "Original: X" tag, or "Translated · Show original" toggle, on reviews and employer replies; application messages carry `original_language` (`application_messages`, `job_applications.message_language`) shown as "Original: X".
- Team: `/business/team` (owners invite with single-use links `org_member_invites` → `/business/join/[token]` → `accept_member_invite()`, change roles/locations, remove; `org_team()` lists members with email for owner/HR).
- Jobs (SPEC phase 3): `jobs` + `job_applications` (migration `20261010060000_jobs.sql`). Public: `/jobs`, job page `/[company]/[location]/jobs/[job]` (JobPosting JSON-LD), open jobs on the location page; data in `lib/data/jobs.ts` (`public_jobs` view). Languages (`lib/languages.ts`, migration `20261011230000_languages.sql`): `jobs.ad_language` (original language of the ad) and `jobs.languages` (expected languages with level, optional), shown on the job page, cards, Careers Hub widget and JobPosting JSON-LD (`skills`), `/jobs?lang=` filter; each expected language becomes a must-have yes/no question for applicants (`languageQuestions`, `components/jobs/languages.ts` `jobQuestions`) and goes into the AI summary. Each job picks `apply_mode`: `quick` (no CV, yes/no question set with must-haves, "Quick apply" badge, `/jobs?quick=1`) or `cv` (upload to the private `cvs` bucket `<job id>/<user id>/…`); questions in `jobs.questions` (`lib/job-questions.ts`: presets, `parseQuestions`, `parseAnswers`, `unmetMusts`). Applicants: `/app/apply/[jobId]` (`components/app/apply-form.tsx`: quick stepper or CV form), `/app/applications`. Employers: `/business/jobs` (create/edit/close, question builder; applications via `job_application_list()` – never exposes user ids, must-have matches first, signed CV links; decisions via `set_application_status()`). Packages per ad (`jobs.tier`: standard posting fee / basic / pro, prices `JOB_PRICING` in `lib/site-config.ts`): publishing and upgrades create `job_orders` (invoiced manually, admin "Orders" tab; published ads can only upgrade). Basic+: AI candidate summary (`lib/candidate-ai.ts` `summarizeApplication`, reads PDF/DOCX CVs, `application_insights`, EN+HU). Pro: AI follow-up questions to the applicant after applying (`application_followups`, `/app/applications/[id]`) and featured in `/jobs`. All packages: Call button (`log_application_call`, not counted as a reply) and messages (`application_messages`, `send_application_message()` counts as a reply; email via `lib/email.ts` with `RESEND_API_KEY`). Decisions count as replies: the ghosting metric comes from applications once a location has 5 decided or 14+ day-old ones (`recompute_location_scores`, nightly `recompute_application_scores`). Applicant reviews from people who applied there get `verification_level = 'application'`.
- Demo data: `supabase/demo/seed_demo.sql` (made-up companies with `demo-` slugs, `companies.is_demo`/`orgs.is_demo`, demo users with `raw_app_meta_data.demo`, emails `@demo.ratethatjob.invalid`); `isDemo` on locations/jobs → `DemoBanner`/`DemoChip` (`components/demo-badge.tsx`), noindex, no JSON-LD, left out of sitemaps. Remove: admin "Demo data" tab (`admin_purge_demo()`) or `select private.purge_demo();`.
- Stripe (`lib/stripe.ts`, live keys on Vercel; migration `20261012030000_stripe.sql`): Pro = Checkout subscription per location (`startProCheckout` in `app/[locale]/business/billing/actions.ts`, HU → HUF else EUR, `toMinor()` keeps HUF whole forints, prices created by lookup_key `rtj_pro_<interval>_<currency>_<amount>`, `trial_end` = our trial or paid period end, at least 48 h ahead), one customer per org (`orgs.stripe_customer_id`, owners can only update `orgs.name`), Customer Portal (`openBillingPortal`, configuration created by metadata `rtj=v1`), UI `components/business/subscribe-pro.tsx` on `/business/locations`. Job ads: saving keeps a draft; publishing/upgrading calls `payForJob()` → `request_job_order()` → one-time Checkout (difference on upgrade) → the job goes live only when `private.fulfill_job_order()` runs (webhook or admin "paid" = bank transfer); trigger `private.guard_job_payment` blocks signed-in users from opening/upgrading directly. Webhook `app/api/stripe/webhook/route.ts`: signature check, `stripe_events` idempotency, `stripe_fulfill_job_order()`, `stripe_sync_subscription()` (active → `paid_until` = period end; past_due/canceled don't extend), payment failed → notification `payment_failed` + email. Admin: `admin_job_order_list()`, `admin_stripe_subscriptions()` with Stripe dashboard links.
- Pro per location: 30-day trial (no card, once per location via `location_trials`) started by `private.approve_claim()` → `location_plans` `trial_ends_at`/`paid_until`; `lib/business.ts` derives `plan` (`trial`/`pro`/`free`) and `pro`. Activation requests `request_pro()` → `plan_orders`, admin "Subscriptions" tab (`admin_decide_plan_order()` extends `paid_until`). Trial notices: pg_cron `process_trials()` (notifications `trial_ending`/`trial_ended`), emailed by `/api/cron/emails`. Banners: `components/business/trial-banner.tsx` (`TrialBanner`, `ProGate` on Index tab and stats). Early warnings and stats are Pro.
- Employer extras: `/business/stats` (monthly volume/score and category windows via `location_stats()`, n ≥ 5), early warnings on the overview (`early_warnings()`: a category down ≥ 0.5 in 60 days), `/business/profile` (`location_profiles` + public `profile-photos` bucket, shown on the location page as "From the employer"). Location pages also list similar workplaces in the same city (`getNearbyLocations`).
- Employers (`app/[locale]/business/`, noindex): `/employers` landing → `/business/claim` (claim requests: phone and website or "no website" required; `account_email` set by the DB from auth – the email method uses it; document method uploads to the private `claim-documents` bucket `<user id>/<claim id>/…` (`lib/claim-upload.ts`); migration `20261012020000_claim_verification.sql`. Admin Claims card: email, phone, website, domain match from `domainCheck()` in `lib/claim-check.ts` (freemail always red), signed document link, "Ask for more info" → `admin_claim_request_info()` + email; the claimant answers on `/business` (`PendingClaims`, `claim_reply()`); approve/reject emails via `lib/claim-emails.ts`, documents deleted on decision. Approve also with `select private.approve_claim('<claim id>')`, without email) → dashboard (overview, reviews & replies/disputes, invite link, locations/team/plan). Data loader: `lib/business.ts`. Invites are email or shareable link only (no SMS). Email invites (`/business/invite`, `components/business/email-invites.tsx`, action `app/[locale]/business/invite/actions.ts`): pasted addresses or CSV (`parseInviteText` in `lib/invites.ts`, optional en/hu column; else account language, else location country), max 200 per send, `create_email_invites()` (skips unsubscribed and anyone invited to the location in 90 days; 500/location and 2 000/org per 24 h), sent with Resend batch (`lib/invite-emails.ts`, `InviteEmail` messages, List-Unsubscribe). Addresses: AES-GCM + HMAC in `lib/invite-crypto.ts` (`INVITE_SECRET`, else derived from the Supabase secret key); one reminder after 5 days from `/api/cron/emails` clears the address, pg_cron `purge_invite_contacts()` clears the rest after use or 7 days. Unsubscribe: `/r/[token]/unsubscribe` and one-click `POST /api/unsubscribe?t=` → `invite_unsubscribe()` (`invite_suppressions`, hash only). Employers see `invite_batch_list()` per batch (reviews received only from 5). Invite links: `/r/[token]` → `/app/rate/[id]?invite=` → `attach_invite()` marks the review invited and delays it.
