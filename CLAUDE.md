# RateThatJob.com

Product & technical spec: @SPEC.md
Project background (Hungarian): docs/osszefoglalo.md · Brand sheet: docs/brand-sheet.webp

## Stack
Next.js (App Router, `cacheComponents`) + TypeScript, Tailwind CSS v4, next-intl, Supabase, Vercel.

- Routing: all pages live under `app/[locale]/`. English at the root, Hungarian under `/hu` (`localePrefix: "as-needed"`, see `i18n/routing.ts`). `proxy.ts` handles locale negotiation.
- UI copy: never hard-code strings – add them to `messages/en.json` and `messages/hu.json`. Client components only receive the namespaces listed in their layout's `NextIntlClientProvider` (`pickMessages` in `lib/client-messages.ts`: root, `app/`, `business/`, `admin/` layouts) – add new client namespaces there.
- Brand tokens: `app/globals.css` (`signal`, `ink`, `paper`, `slate`, `mist`, `tracking-brand`, `tracking-tagline`). Never use `signal` green as text on a light background.
- Brand files: `public/brand/` (logo on light/dark, icon, app icon).
- Supabase clients: `lib/supabase/server.ts`, `lib/supabase/client.ts`. Env vars: `.env.example`.
- Public data: `lib/data/index.ts` (`"use cache"`). Reads the `public_locations` / `public_reviews` views when Supabase env vars are set, otherwise `lib/data/sample.ts`.
- Database: `supabase/migrations/` (schema + RLS), applied automatically before every Vercel build by `scripts/migrate.mjs` (uses `POSTGRES_URL_NON_POOLING` from the Supabase ↔ Vercel integration; tracked in `supabase_migrations.schema_migrations`). Migrations must be new files, never edits of applied ones, `supabase/seed.sql` (local sample data). The public never reads `reviews`, `profiles` or `invites` directly – only through the `public_*` views. Score aggregates: `recompute_location_scores()` (service role).
- Public routes: `app/[locale]/[company]/[location]` (location page, JSON-LD, hreflang) and `.../reviews` (filters, pagination). These block instead of streaming (`instant = false`) so unknown slugs return a real 404.

- Reviewer flow (`app/[locale]/app/`, noindex): `sign-in` (email OTP, OAuth: Apple, Google, Facebook) → `/auth/callback` → `welcome` (display name) → `rate` (workplace search) → `rate/[locationId]` (3-step form, `components/app/review-form.tsx`). Server actions: `app/[locale]/app/actions.ts`; validation: `lib/review-input.ts`. `proxy.ts` refreshes the Supabase session on `/app` paths only.
- Publishing: reviews are inserted as `pending_moderation`; a DB trigger (`private.moderate_review`) schedules them (anonymity delay) or holds them for the manual queue with `hold_reason` (contact details/links, fraud signals: `burst`, `new_account`, `many_locations`), and pg_cron runs `publish_due_reviews()` every 15 minutes. After submit, `processNewReview()` (`lib/translation-jobs.ts`) runs the Claude moderation check (`lib/moderate.ts`; flagged → `hold_review()`, reason `ai:…`) and then translation. Verification files go to the private `verifications` storage bucket under `<user id>/`.

- Workplaces: reviewers add missing ones via `create_workplace()` (`/app/rate/new`); company pages at `app/[locale]/[company]`. With `GOOGLE_PLACES_API_KEY` + `SUPABASE_SECRET_KEY`, `/app/rate` and `/app/rate/new` also search Google Maps (`lib/places.ts`, Places API New, session tokens; actions in `app/[locale]/app/rate/places/actions.ts`, UI `components/app/place-search.tsx`): one workplace per `google_place_id`, created server-side by `workplace_from_place()` (service role only; attaches the place id to a matching hand-entered location).
- Account (`/app/account`): reviews and statuses, "I've left this job" (`mark_job_ended`), JSON export, sign out, delete account (`delete_my_account`).
- Admin (`app/[locale]/admin`, noindex): claims, moderation, documents, disputes, reports tabs, calling the `admin_*` RPCs; tools: legal entities (`admin_link_entity` → verified "Operated by"), workplaces (change company/location slugs → `slug_redirects`, resolved by `findRedirect()` in `lib/data/redirects.ts` with a 301) and CSV import (`admin_import_locations`, seeded workplaces). Admins are rows in `public.admins`. Decided verification files are deleted from storage.
- Follows & notifications: `toggle_follow()` (`components/follow-button.tsx` on the location page, list on `/app/account`); DB triggers write in-app `notifications` (review published, employer reply, application status, new review/job at a followed place, new application for managers), shown at `/app/notifications` and as the bell in `AccountLink`. Helpful votes: `vote_helpful()`, `helpful_count` in `public_reviews`. Admin "Metrics" tab: `admin_metrics()` (SPEC PMF signals).
- Reports: readers flag reviews on public pages (`components/report-button.tsx` → `reports`), one open report per person and review.
- Site chrome & static pages: `SiteHeader` (desktop nav, `MobileMenu` on phones, `LocaleSwitch` dropdown with flags), `SiteFooter` rendered from the locale layout through `FooterGate` (hidden on `/business`, `/admin` and the rate/apply forms). `/about`, marketing pages `/ratethatjob-index` (how the Index works, example badges from `lib/marketing-examples.ts`) and `/career-page` (jobs widget, `components/marketing/jobs-widget-example.tsx`; both with FAQ, in the sitemap and reserved slugs), `/pricing` (plans; prices in `lib/site-config.ts` `PRICING`, null = on request), legal pages `/terms`, `/privacy`, `/cookies`, `/imprint` from `content/legal/<page>.<locale>.md` (rendered by `lib/markdown.tsx`; `{{name}}` etc. filled from `OPERATOR` in `lib/site-config.ts`). FAQ blocks: `components/faq.tsx` (FAQPage JSON-LD).
- Discovery & SEO: `/search` (noindex, follow), city hubs `/city/[city]` and `/city/[city]/[category]` (`CATEGORY_SLUGS` in `lib/format.ts`), sitemap index `app/sitemap.xml/route.ts` → `app/sitemaps/*`, `app/robots.ts`, OG image per location (`opengraph-image.tsx`, Archivo fonts in `assets/fonts`).
- RateThatJob Index: `lib/rtj-index.ts` (SVG badges), `/embed/[id].svg?style=&locale=`, `/embed/[id]` (iframe card), `/embed/[id]/seal.svg`, `/api/public/locations/[id]/index` (JSON, CORS open), `public/widget.js`, generator at `/business/index` (also lists embedding websites from `embed_referrers`, recorded by `recordEmbed()`; badges are browser-cached only so every site is counted). Score shown from 5 reviews; seal at 4.0+ with 10+ verified. Jobs widget: `<div data-rtj-jobs="job|location|company" data-id data-theme data-locale>` in `public/widget.js` (Shadow DOM, featured jobs first, RateThatJob Index footer always shown) reads `/api/public/jobs?job=|location=|company=&locale=` (`lib/jobs-widget.ts`, open jobs from `public_jobs` only, CORS open, browser-cached, per-IP limit in `lib/rate-limit.ts`, `recordEmbed()` per location); Apply goes to `/app/apply/[id]?ref=embed&from=<host page>` in a new tab → `job_applications.source = 'embed'` and a "Back to the company's website" button. Generator: "Jobs" tab on `/business/index` (`components/business/jobs-embed-generator.tsx`).
- Machine translation: `lib/translate.ts` (Claude, `ANTHROPIC_API_KEY`) detects the language and translates review/reply text into every locale; `lib/translation-jobs.ts` stores it with the service-role client (`lib/supabase/admin.ts`, `SUPABASE_SECRET_KEY`). Runs via `after()` on submit/reply and daily from `/api/cron/translate` (`vercel.json`, `CRON_SECRET`). Skipped silently when keys are missing.
- Team: `/business/team` (owners invite with single-use links `org_member_invites` → `/business/join/[token]` → `accept_member_invite()`, change roles/locations, remove; `org_team()` lists members with email for owner/HR).
- Jobs (SPEC phase 3): `jobs` + `job_applications` (migration `20261010060000_jobs.sql`). Public: `/jobs`, job page `/[company]/[location]/jobs/[job]` (JobPosting JSON-LD), open jobs on the location page; data in `lib/data/jobs.ts` (`public_jobs` view). Each job picks `apply_mode`: `quick` (no CV, yes/no question set with must-haves, "Quick apply" badge, `/jobs?quick=1`) or `cv` (upload to the private `cvs` bucket `<job id>/<user id>/…`); questions in `jobs.questions` (`lib/job-questions.ts`: presets, `parseQuestions`, `parseAnswers`, `unmetMusts`). Applicants: `/app/apply/[jobId]` (`components/app/apply-form.tsx`: quick stepper or CV form), `/app/applications`. Employers: `/business/jobs` (create/edit/close, question builder; applications via `job_application_list()` – never exposes user ids, must-have matches first, signed CV links; decisions via `set_application_status()`). Packages per ad (`jobs.tier`: standard posting fee / basic / pro, prices `JOB_PRICING` in `lib/site-config.ts`): publishing and upgrades create `job_orders` (invoiced manually, admin "Orders" tab; published ads can only upgrade). Basic+: AI candidate summary (`lib/candidate-ai.ts` `summarizeApplication`, reads PDF/DOCX CVs, `application_insights`, EN+HU). Pro: AI follow-up questions to the applicant after applying (`application_followups`, `/app/applications/[id]`) and featured in `/jobs`. All packages: Call button (`log_application_call`, not counted as a reply) and messages (`application_messages`, `send_application_message()` counts as a reply; email via `lib/email.ts` with `RESEND_API_KEY`). Decisions count as replies: the ghosting metric comes from applications once a location has 5 decided or 14+ day-old ones (`recompute_location_scores`, nightly `recompute_application_scores`). Applicant reviews from people who applied there get `verification_level = 'application'`.
- Employer extras: `/business/stats` (monthly volume/score and category windows via `location_stats()`, n ≥ 5), early warnings on the overview (`early_warnings()`: a category down ≥ 0.5 in 60 days), `/business/profile` (`location_profiles` + public `profile-photos` bucket, shown on the location page as "From the employer"). Location pages also list similar workplaces in the same city (`getNearbyLocations`).
- Employers (`app/[locale]/business/`, noindex): `/employers` landing → `/business/claim` (claim requests, approved by an admin with `select private.approve_claim('<claim id>')`) → dashboard (overview, reviews & replies/disputes, invite link, locations/team/plan). Data loader: `lib/business.ts`. Invite links: `/r/[token]` → `/app/rate/[id]?invite=` → `attach_invite()` marks the review invited and delays it.
